## Quick Start

If you're already familiar with the Snakemake version, here's what you need to know:

### Replace your run command:

**Snakemake (old):**
```bash
./run.sh -i SampleContrastSheet.xlsx -o my_analysis
```

**Nextflow (new):**
```bash
./run_nextflow.sh -i SampleContrastSheet.xlsx -o my_analysis
```

That's it! The input format and output structure remain the same.

## Key Differences

### Workflow Engine

| Feature | Snakemake | Nextflow |
|---------|-----------|----------|
| **Execution Model** | Pull-based (backward chaining) | Push-based (dataflow) |
| **Resume Capability** | File timestamp-based | Hash-based, more reliable |
| **Cloud Support** | Limited | Native AWS, Google Cloud, Azure |
| **Containerization** | Via conda | Docker, Singularity, Podman |
| **DSL** | Python-based | Groovy-based DSL2 |

### File Structure

**Snakemake:**
```
miND/
├── Snakefile          # Main workflow
├── config.yaml        # Configuration
└── run.sh            # Run script
```

**Nextflow:**
```
miND/
├── main.nf           # Main workflow (replaces Snakefile)
├── nextflow.config   # Configuration (similar to config.yaml)
├── run_nextflow.sh   # Run script (similar to run.sh)
└── Snakefile        # Still available for legacy support
```

## Command Line Comparison

### Basic Execution

| Snakemake | Nextflow |
|-----------|----------|
| `./run.sh -i input.xlsx` | `./run_nextflow.sh -i input.xlsx` |
| `./run.sh -i input.xlsx -o output_dir` | `./run_nextflow.sh -i input.xlsx -o output_dir` |
| `./run.sh -i input.xlsx -k` | `./run_nextflow.sh -i input.xlsx -k` |

### Advanced Options

**Snakemake:**
```bash
snakemake --use-conda \
  --conda-prefix=envs/tmp \
  --cores 8 \
  --config sampleSheet=input.xlsx
```

**Nextflow:**
```bash
nextflow run main.nf \
  --sampleSheet input.xlsx \
  -profile conda \
  -resume
```

### Resume a Failed Run

**Snakemake:**
```bash
# Snakemake automatically resumes based on file timestamps
./run.sh -i input.xlsx
```

**Nextflow:**
```bash
# Use -resume flag for more reliable resumption
./run_nextflow.sh -i input.xlsx -resume
```

## Configuration Changes

### Thread Allocation

**Snakemake (config.yaml):**
```yaml
threads:
  high: 6
  medium: 4
  low: 2
```

**Nextflow (nextflow.config):**
```groovy
params {
    threads_high = 6
    threads_medium = 4
    threads_low = 2
}
```

### Reference Data Paths

Both versions use the same paths:

```yaml
repoPath: "repository/data"
miRBaseVersion: "22.1"
rnacentralVersion: "19.0"
```

### Species Configuration

The species configuration remains identical in both versions. No changes needed.

## Output Compatibility

### Output Directory Structure

The Nextflow version produces **identical output structure** to the Snakemake version:

```
output/
└── [analysis_name]/
    ├── fastqc_raw/
    ├── fastqc_trimmed/
    ├── fastq_trimmed/
    ├── mapping_bowtie_*/
    ├── mapping_mirdeep2_miRNA/
    ├── analysis_sampleMappingStats/
    ├── analysis_quantifySampleMappings/
    ├── analysis_differentialExpression/

    ├── analysis/

    └── [DATE]_[PROJECTID]_MINDreport.zip
```

### File Naming

All output files maintain the same naming conventions, ensuring compatibility with downstream analyses.

### Report Format

The HTML reports generated by both versions are identical.

## Troubleshooting

### Common Migration Issues

#### Issue 1: "Nextflow command not found"

**Solution:**
```bash
# Install Nextflow
conda install -c bioconda nextflow
# OR
curl -s https://get.nextflow.io | bash
```

#### Issue 2: Conda environments not working

**Solution:**
```bash
# Ensure conda profile is active
./run_nextflow.sh -i input.xlsx -profile conda

# OR specify conda frontend
nextflow run main.nf --sampleSheet input.xlsx -with-conda
```

#### Issue 3: Different results between Snakemake and Nextflow

**Cause:** This should not happen as both use the same tools and parameters.

**Solution:**
1. Ensure the same version of reference databases
2. Check that parameters in the Excel file are identical
3. Verify conda environment versions match

#### Issue 4: Work directory taking up too much space

**Solution:**
```bash
# Clean work directory after successful run
./run_nextflow.sh -i input.xlsx
# Work directory is auto-cleaned unless -k flag is used
```

### Performance Comparison

Expected performance characteristics:

| Metric | Snakemake | Nextflow |
|--------|-----------|----------|
| **Initial Setup** | Faster | Slightly slower (hash computation) |
| **Resume Speed** | Slower | Faster (better caching) |
| **Memory Usage** | Lower | Slightly higher (JVM overhead) |
| **Execution Time** | Baseline | Similar (±5%) |

## FAQ

### Q: Can I use both versions side-by-side?

**A:** Yes! Both `Snakefile` and `main.nf` can coexist in the same directory. Use different run scripts:
- `./run.sh` for Snakemake
- `./run_nextflow.sh` for Nextflow

### Q: Do I need to recreate conda environments?

**A:** No. Nextflow can use the same conda environments as Snakemake. The `.yml` files in the `envs/` directory are shared.

### Q: Can I migrate mid-analysis?

**A:** Not recommended. Complete your current analysis with the original workflow engine, then switch for new analyses.

### Q: Which version should I use?

**A:** 
- **Use Nextflow if:**
  - You need cloud execution (AWS, Google Cloud, Azure)
  - You want better resume reliability
  - You plan to use containers (Docker/Singularity)
  - You need advanced pipeline features

- **Use Snakemake if:**
  - You're already familiar with it
  - You have existing custom modifications
  - You prefer Python-based syntax

### Q: Are the results identical?

**A:** Yes. Both versions:
- Use the same tools (cutadapt, bowtie, miRDeep2, etc.)
- Use the same parameters
- Use the same R scripts for analysis
- Generate identical output files

### Q: What about custom modifications?

**A:** If you've modified the Snakefile:
- Document your changes
- Apply equivalent changes to `main.nf`
- Test thoroughly before production use

### Q: Can I convert back to Snakemake?

**A:** Yes. The Snakefile is still maintained and available. Simply use `./run.sh` instead of `./run_nextflow.sh`.
